# Migration Guide: v0.11 → v0.12

This guide covers the breaking changes in v0.12.

- [**Idempotent `payment.requestPayment`**](#idempotent-paymentrequestpayment), the product supplies the payment id, and
  a short payment has its own terminal status

> **v0.12 is wire-incompatible with v0.11 for `host_payment_request` and `host_payment_status_subscribe`**, whose
> request, response, error and status shapes changed, so hosts and products must be upgraded together. No method id
> moves, and every other method is byte-identical. There is no session or key impact.

---

## Idempotent `payment.requestPayment`

`host_payment_request`, where the product offloads balance to a destination account, gets the same treatment as
`host_payment_top_up`. It used to return a host-issued `PaymentReceipt { id: string }`; the product now supplies the id,
and the request returns nothing on success.

### The id is supplied by the product

`PaymentId` changes from a string to an opaque **32-byte** value — `[u8; 32]` on the wire, `Uint8Array` in TypeScript,
the same shape as the top up id. A product can be terminated between the call and its response, which would lose a
host-issued id; an id the product wrote down first survives that. It is also the idempotency key: registering an id the
host already knows fails with the new `PaymentRequestErr.AlreadyExists` rather than paying twice, so a retry after an
ambiguous failure is safe.

`PaymentReceipt` is gone, and `host_payment_status_subscribe` now takes the 32-byte id.

### The host owns the payment once it is registered

A registered payment is driven to a terminal status by the host, across a full host restart if need be. Statuses never
advance once terminal — `Completed`, `Failed` or the new `PartiallyClaimed` — no action is taken after that point, and
they are kept indefinitely.

### `PaymentStatus` gained `PartiallyClaimed`

`PartiallyClaimed(u128)` is terminal and carries the amount that actually reached the destination, less than requested.
It is appended after `Failed`, so the SCALE indices of `Processing`, `Completed` and `Failed` do not move.

### Products

```ts
// v0.11
const { id } = await payments.requestPayment(500_000n, destination);
payments.subscribePaymentStatus(id, onStatus);

// v0.12
const id = crypto.getRandomValues(new Uint8Array(32)); // persist this before calling
await payments.requestPayment(500_000n, destination, id);
// resolves as soon as the host registered the payment

const sub = payments.subscribePaymentStatus(id, status => {
  switch (status.type) {
    case 'processing':
      return;
    case 'completed':
      return done(); // terminal
    case 'failed':
      return failed(status.reason); // terminal
    case 'partiallyClaimed':
      return short(status.actualClaimed); // terminal
  }
});
sub.onInterrupt(reason => {
  // PaymentStatusErr.PaymentNotFound — the host does not know this id
});
```

The optional trailing purse argument (`from`) is unchanged and now sits after the id:
`requestPayment(amount, destination, id, from?)`.

`subscribePaymentStatus` now returns `Subscription<PaymentStatusErr>`, like `subscribeTopUpStatus`: `onInterrupt`
receives the `PaymentStatusErr` itself instead of the `{ tag: 'v1', value }` envelope. A `switch` over
`PaymentStatus['type']` must handle `partiallyClaimed`.

### Hosts

`handlePaymentRequest` gains `id` on its params and answers `ok(undefined)` instead of a receipt:

```ts
container.handlePaymentRequest(async ({ amount, destination, id }, { ok, err }) => {
  // `id` arrives as a raw 32-byte Uint8Array — key storage by its hex form.
  const key = toHex(id);
  if (payments.has(key)) return err(new PaymentRequestErr.AlreadyExists());
  if (!(await showPaymentConfirmation({ amount, destination }))) return err(new PaymentRequestErr.Rejected());
  payments.register(key, { amount, destination });
  return ok(undefined);
});
```

`handlePaymentStatusSubscribe` receives the 32-byte id and may send the new terminal status:

```ts
container.handlePaymentStatusSubscribe((id, send, interrupt) => {
  const payment = payments.get(toHex(id));
  if (!payment) {
    interrupt(new PaymentStatusErr.PaymentNotFound());
    return () => {};
  }
  return payment.track(status => {
    // ...
    if (status.partial) send({ tag: 'PartiallyClaimed', value: status.delivered });
  });
});
```

### `PaymentRequestErr` gained `AlreadyExists`

```ts
// v0.11
PaymentRequestErr.Rejected;
PaymentRequestErr.InsufficientBalance;
PaymentRequestErr.Unknown;

// v0.12
PaymentRequestErr.AlreadyExists; // this id is already registered
PaymentRequestErr.Rejected;
PaymentRequestErr.InsufficientBalance;
PaymentRequestErr.Unknown;
```

`AlreadyExists` is the first variant, so the SCALE indices of the other three shift by one.
