# Migration Guide: v0.9 → v0.10

This guide covers the breaking changes and new APIs in v0.10. Everything here is in the host to product wire protocol
(`host-api`, `host-api-wrapper`, `host-container`).

- [**The CallError transport envelope**](#the-callerror-transport-envelope), a new wire layer on every response and interrupt
- [**polkadot-api v3**](#polkadot-api-v3), signers become `TxCreator`s
- [**New APIs**](#new-apis): coin payment, worker keep-alive, local storage subscribe, chain info, host info and product context, host locale

> **v0.10 is wire-incompatible with v0.9.** Every response and interrupt now carries a `CallError<D>` envelope, a
> byte-level change on the error path of methods that already existed, so hosts and products must be upgraded together.
> There is no session or key impact, so no re-pairing.

---

## The CallError transport envelope

truapi wraps every method result in a `CallError<D>` on the failure path. `Domain` carries the method's own business
error; the other four variants are transport or host failures that no method's error type describes:

- `Denied`, the host refused the call
- `Unsupported`, the host does not implement the method
- `MalformedFrame { reason }`, the request did not decode
- `HostFailure { reason }`, the handler threw

v0.10 syncs to this. Every `_response` codec now uses `CallResult(ok, domainErr)` instead of scale-ts `Result`, and every
typed subscription interrupt is wrapped the same way. The wire bytes gain the `CallError` layer; the decoded value does
not change shape for the common paths, so nothing changes for code that goes through the wrapper.

### Products

`host-api-wrapper` folds a transport failure into the method's own error type, so a product keeps a single error to
handle. Nothing to change unless you read a raw subscription payload or response yourself. If you do, guard it:

```ts
import { isCallErrorFailure } from '@novasamatech/host-api';

hostApi.someSubscribe(args, payload => {
  if (payload.tag !== 'v1') return;
  if (isCallErrorFailure(payload.value)) return; // transport failure, not a domain reason
  // payload.value is the domain value
});
```

`CALL_ERROR_FAILURE` and `CallErrorTransportFailure` are exported alongside `isCallErrorFailure` for code that wants to
inspect the failure.

### Hosts

A handler that returns `ok(...)` or `err(domainErr)` needs no change; the envelope is applied by the transport. The
container also fills in the transport variants on its own:

- a method with no registered handler answers `Unsupported` instead of a business `Unknown` error
- a request that does not decode to the running version answers `MalformedFrame`
- a handler that throws answers `HostFailure` instead of leaving the caller's promise hung

`host-api-wrapper` folds all three into the method's own error type, so a product still sees one error.

## polkadot-api v3

v0.10 requires polkadot-api v3 (`>=3`). v3 replaces the `PolkadotSigner` transaction model with `TxCreator`; see the
[polkadot-api v3 migration guide](https://papi.how/v3migration/) for the full API delta. In this SDK the change is
contained to the signer factories.

### Signers are now `TxCreator`s

The signer factories return a v3 `TxCreator` instead of a `PolkadotSigner`:

- `accounts.getProductAccountSigner(account)`
- `accounts.getLegacyAccountSigner(account)`
- `allowance.getBulletinSigner(sessionId, productId)` (host-papp)

A `TxCreator` is a callable that produces a SCALE-encoded extrinsic, and (for signer creators) still exposes
`publicKey` and `signBytes`. Pass it wherever v3 expects a `TxCreator` — the same places v2 took a `PolkadotSigner`.
Code that only read `publicKey` or called `signBytes` needs no change.

The product-account creator keeps host-delegated signing: a real signature is produced by the host via
`host_create_transaction`, so the host still owns extension inference and signing. A mocked signature (fee estimation)
on a v4 payload is built locally with a zero-filled signature and no host round-trip; other versions (e.g. v5) fall
through to the host.

### Regenerate descriptors

v3 descriptors are not compatible with v2. Regenerate them for any package that ships a `.papi` directory:

```bash
npm run papi:update   # or `npx papi generate` to rebuild from cached metadata
```

## New APIs

### Coin payment (RFC 0017)

Firewalled purses, receivables and cheques. `createCoinPayment()` returns request methods (`createPurse`, `queryPurse`,
`createReceivable`, `createCheque`) and streaming operations (`rebalancePurse`, `deletePurse`, `deposit`, `refund`,
`listenForPayment`) that report clearing status through a callback and return a `Subscription`.

```ts
import { createCoinPayment } from '@novasamatech/host-api-wrapper';

const coinPayment = createCoinPayment();
const purse = await coinPayment.createPurse('Terminal purse');
const receivable = await coinPayment.createReceivable(purse);
const cheque = await coinPayment.createCheque(purse, receivable, 1000);

const sub = coinPayment.deposit(cheque, status => {
  if (status.tag === 'Done') console.log('cleared', status.value.cleared);
});
sub.onInterrupt(err => console.log('interrupted', err));
```

Hosts implement the `handleCoinPayment*` container handlers. These fill protocol ids 136-163, which had been reserved
with a manual index skip; the skip is gone, so a host that pinned raw method ids should confirm `sign_vrf` still lands on
164.

### Worker keep-alive

Holds a product's worker alive while a background task runs, past the point its surface goes away.

```ts
import { createWorker } from '@novasamatech/host-api-wrapper';

const worker = createWorker();
const id = await worker.beginOperation('sync');
// ... background work ...
await worker.endOperation(id); // idempotent
```

Hosts implement `handleWorkerBeginOperation` and `handleWorkerEndOperation` and keep the worker running while it holds at
least one open operation.

### Local storage subscribe

`subscribeBytes`, `subscribeString` and `subscribeJSON` on the storage wrapper emit the current value immediately, then on
every later write or clear. `undefined` means the key is absent.

```ts
const sub = storage.subscribeJSON('config', value => console.log(value));
sub.unsubscribe();
```

Hosts implement `handleLocalStorageSubscribe`.

### Chain info

`chainGetChainInfo` resolves a logical chain role to its concrete network name and genesis hash, so a product can name a
role instead of hard-coding a genesis hash.

```ts
const info = await hostApi.chainGetChainInfo(enumValue('v1', { chain: 'AssetHub' }));
```

`ChainIdentifier` is `Relay | AssetHub | People | Bulletin`; failures use `ChainInfoErr` (`NotSupported`, `Unknown`).
Hosts implement `handleChainGetChainInfo`.

### Host info and product context

`createSystem()` reports which host is running the product and which product it is. `info()` returns the host's
`platform`, `name` and `version`; `getProductContext()` returns the `productId` bound to the current host runtime.

```ts
import { createSystem } from '@novasamatech/host-api-wrapper';

const system = createSystem();
const host = await system.info(); // { platform: 'Desktop', name: 'Polkadot Desktop', version: '1.2.3' }
const { productId } = await system.getProductContext();
```

`platform` is `Web | Android | Ios | Desktop | Cli | Unknown`. Hosts implement `handleInfo` and
`handleGetProductContext`.

### Host locale

`createLocaleProvider().subscribeLocale(cb)` delivers the language the host presents its interface in as a BCP 47 tag,
once on subscribe and again on every change.

```ts
import { createLocaleProvider } from '@novasamatech/host-api-wrapper';

const sub = createLocaleProvider().subscribeLocale(locale => console.log(locale.languageTag));
sub.unsubscribe();
```

Hosts implement `handleLocaleSubscribe`.
