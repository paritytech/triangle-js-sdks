# Migration Guide: v0.8 → v0.9

This guide covers all breaking changes and new APIs introduced in v0.9. It is split by SDK so each area can be migrated — and published — independently:

- [**host-api**](#host-api) — the host ↔ product wire protocol (`host-api`, `host-api-wrapper`, `host-container`)
- [**host-papp**](#host-papp) — the Polkadot Mobile integration layer (`host-papp`, `host-papp-react-ui`)
- [**Common**](#common) — low-level pieces shared across SDKs (`@novasamatech/scale`)

> **v0.9 is wire-incompatible with v0.8 for anything carrying a product account.** RFC-0022 turns the account derivation index into an enum selector, which changes the encoded bytes of every request that names a product account, a proof context, a `ProductAccount` top-up source or a `SmartContractAllowance`. Hosts, products and the paired Polkadot Mobile build must be upgraded together. Existing SSO pairings survive — the session blob and the existing `RemoteMessage` variant indexes are unchanged — but a v0.8 peer will mis-decode those requests, so re-pairing is not a substitute for upgrading.

---

# host-api

The host ↔ product wire protocol (`host-api`, `host-api-wrapper`, `host-container`).

## TL;DR

1. **Product accounts are addressed by a selector, not a bare `u32`** (RFC-0022). Products keep passing a plain number — the ergonomic `AccountSelector` is `number | Uint8Array`:

   ```ts
   await accounts.getProductAccount('my-product.dot', 0); // unchanged
   await accounts.getProductAccount('my-product.dot', raw32); // new: byte-valued selector
   ```

   **Hosts** must expand it: `derivationIndexBytes(index)` from `@novasamatech/host-container`.

2. **Proof-context suffixes are that same selector**, no longer a hex string:

   ```diff
   - const context = ['product.dot', '0x00'];
   + const context: ProofContext = ['product.dot', 0];
   ```

3. **`createTransaction` — `genesisHash` is a hex string**, not a `Uint8Array`:

   ```diff
   - genesisHash: fromHex(checkGenesis.additionalSigned),
   + genesisHash: checkGenesis.additionalSigned,
   ```

4. **Verify, don't edit:** fixed-size codecs (`AccountId`, signatures, `Topic`, `genesisHash`, …) now throw on over-long values instead of silently truncating. Correctly sized values encode exactly as before.

---

## Account selector (RFC-0022)

Product accounts live at `//product//{productId}/{index}` — two hard junctions and a soft one whose chain code is a **32-byte** derivation index. v0.8 addressed accounts with a bare `u32`; v0.9 addresses them with an enum selector so a caller can also name an account by those 32 bytes directly:

```
enum DerivationIndex { Index(u32), Raw([u8; 32]) }
```

`Index` stays the primary form — plain indices keep a product's accounts enumerable. `Raw` is the escape hatch for byte-valued selectors.

This changes the wire encoding of every request carrying:

| | |
|---|---|
| `ProductAccountId` | `accountGet`, `accountSignVrf`, sign-payload / sign-raw, `createTransaction`, `statementStoreCreateProof` |
| `ProductProofContext` suffix | `accountGetAlias`, `accountCreateProof` |
| `PaymentTopUpSource.ProductAccount` | `paymentTopUp` |
| `AllocatableResource.SmartContractAllowance` | `resourceAllocation` |

### Products

The wrapper APIs take the ergonomic form — `AccountSelector = number | Uint8Array` — so existing call sites that pass a number **need no change**:

```ts
import type { AccountSelector, ProductAccount, ProofContext } from '@novasamatech/host-api-wrapper';

await accounts.getProductAccount('my-product.dot', 0);
await accounts.signVrf('my-product.dot', 0, transcriptLabel, items);
await payments.topUp(1_000_000n, { type: 'productAccount', derivationIndex: 0 });
await statementStore.createProof(['my-product.dot', 0], statement);
```

`ProductAccount.derivationIndex` is now `AccountSelector` rather than `number`; code that reads it back and does arithmetic on it must narrow first (`typeof idx === 'number'`).

If you build wire payloads by hand rather than through the wrapper, normalize with `derivationIndexOf`:

```ts
import { derivationIndexOf } from '@novasamatech/host-api';

derivationIndexOf(5); // { tag: 'Index', value: 5 }
derivationIndexOf(raw32); // { tag: 'Raw', value: raw32 } — throws if not exactly 32 bytes
```

### Hosts

Container handlers receive the selector in its wire form and must expand it to the 32 bytes used as the soft junction's chain code. Past that boundary only the 32-byte form exists:

```diff
+ import { derivationIndexBytes } from '@novasamatech/host-container';

  container.handleAccountGet(async ([dotnsId, derivationIndex], { ok, err }) => {
-   const account = await getProductAccount(dotnsId, derivationIndex);
+   const account = await getProductAccount(dotnsId, derivationIndexBytes(derivationIndex));
    // …
  });
```

The same expansion applies in `handleStatementStoreCreateProof`, `handlePaymentTopUp` (`source.value` on the `ProductAccount` tag), `handleRequestResourceAllocation` (`SmartContractAllowance`), `handleAccountSignVrf` and the signing handlers.

`@novasamatech/host-container` exports three helpers:

```ts
import { INDEX_MAGIC, derivationIndexBytes, indexBytes } from '@novasamatech/host-container';

INDEX_MAGIC; // blake2b256("product-account-index")[..28]
indexBytes(0); // u32 little-endian ++ INDEX_MAGIC
derivationIndexBytes({ tag: 'Index', value: 5 }); // === indexBytes(5)
derivationIndexBytes({ tag: 'Raw', value: raw32 }); // === raw32
```

> **Both forms can name one account.** Anything keyed by account — caches, permission grants, allowance records — must key on the **expanded 32 bytes**, never on the selector as received. `INDEX_MAGIC` is what keeps the two spaces apart: per RFC-0022 it separates them "for all practical use cases" — a raw value collides with a plain index only if it ends in the magic. The RFC requires no validation of that case and `derivationIndexBytes` performs none (it only length-checks), so a host that treats a raw selector from an untrusted product as security-relevant has to reject the tail itself.

> **Stock tooling cannot express this path.** The 32-byte index is not a typeable path segment, so `//product//browse.dot/5` in `polkadot-js` or `subkey` does **not** derive index `5`.

## Proof-context suffix

`ProductProofContext` is `[productId, suffix]`, and the suffix is now the same selector as an account's derivation index (RFC-0004 as amended by RFC-0022) instead of a hex string. It expands to the same 32 bytes, so the alias ↔ account mapping is the identity on it.

```diff
// host-api-wrapper
- const context: [string, string] = ['product.dot', '0x00'];
+ const context: ProofContext = ['product.dot', 0];

  await accounts.getContextualAlias(context, ring);
  await accounts.createRingVRFProof(context, ring, message);
```

```diff
// host-papp — takes the wire form
- const context = ['product.dot', '0x00'];
+ const context = ['product.dot', { tag: 'Index', value: 0 }];
```

---

## `createTransaction` genesisHash is hex

`genesisHash` on the `createTransaction` / `createTransactionWithLegacyAccount` payloads is a `0x`-prefixed hex string instead of a `Uint8Array`, matching every other `genesisHash` in the SDK.

**The wire encoding is unchanged** — 32 raw bytes either way — so this one does not force a coordinated host/product upgrade. Only TypeScript callers that build the payload need to change:

```diff
  const txPayload = {
    signer,
-   genesisHash: fromHex(checkGenesis.additionalSigned), // when you had a hex string
+   genesisHash: checkGenesis.additionalSigned,
    // …
  };
```

```diff
  const txPayload = {
    signer,
-   genesisHash: checkGenesis.additionalSigned, // when you had bytes, e.g. from papi
+   genesisHash: toHex(checkGenesis.additionalSigned),
    // …
  };
```

Every other field on the payload (`callData`, `extra`, `additionalSigned`) stays a `Uint8Array`.

---

## Fixed-size codecs no longer truncate silently

`host-api`'s fixed-size codecs — `AccountId`, signatures, `Topic`, `genesisHash`, `RawDerivationIndex` and the rest — now go through the new `Bytes` / `Hex` codecs in [`@novasamatech/scale`](#bytes-codec-with-a-known-size). A wrong-sized value used to encode silently: scale-ts truncated over-long values and let shorter ones corrupt the stream. Now an over-long value **throws** and a shorter one is zero-padded.

Correctly sized values encode exactly as before, so there is nothing to edit. But if your host or product was accidentally passing a wrong-sized account id or topic, the failure moves from a corrupted downstream decode to a thrown error at the encode site — worth a run through your signing and statement-store paths before shipping.

# host-papp

The Polkadot Mobile integration layer (`host-papp`, `host-papp-react-ui`).

## TL;DR

1. **`AllocatedResource.AutoSigning` carries only `productRootPrivateKey`** — `productDerivationSecret` is gone.
2. **New: `UserSession.getProductSubtree(productId)`** — required to derive product account public keys locally now that `//product//{productId}` is a hard junction.
3. Proof-context suffixes take the RFC-0022 selector; see [proof-context suffix](#proof-context-suffix).

---

## Breaking changes

### `AutoSigning` payload

`//product//{productId}` is now a **hard** junction, so the allocated auto-signing key exposes exactly one product's subtree and the secret path component it used to be paired with is meaningless:

```diff
  // AllocatedResource.AutoSigning
  {
-   productDerivationSecret: string,
    productRootPrivateKey: Uint8Array, // Sr25519PrivateKey ++ Sr25519Nonce (64 bytes)
  }
```

Hosts that stored or forwarded `productDerivationSecret` must drop it; `productRootPrivateKey` alone signs and soft-derives `/{index}` below the product root.

---

## New features

### `UserSession.getProductSubtree(productId)`

Because the product junction is hard, the user's root public key no longer determines product account public keys. The host asks the paired device for the product-subtree public key once, then soft-derives account public keys locally from it:

```ts
const subtreeKey = await currentSession.getProductSubtree('product.dot');

subtreeKey.match(
  publicKey => cacheProductSubtree('product.dot', publicKey), // one round trip per product, ever
  error => console.error('subtree lookup failed:', error),
);
```

The request is **consent-free** — the response carries no secret material, so it needs no user prompt. Cache the result; only `AutoSigning` (which does carry secret material) requires consent.

On the wire this is a new `ProductSubtreeRequest` / `ProductSubtreeResponse` pair, **appended** to the `RemoteMessage` enum so every existing variant index is unchanged.

# Common

Low-level pieces in `@novasamatech/scale`, shared across SDKs.

## `Bytes` codec with a known size

`@novasamatech/scale` gains a `Bytes` codec wrapping scale-ts's, and `Hex` is now built on it. Both expose the fixed size as `codec.size`:

```ts
import { Bytes, Hex } from '@novasamatech/scale';

Bytes(32).size; // 32
Hex(32).size; // 32 — byte size, not hex-string length
Bytes().size; // undefined — length-prefixed, no fixed size
```

`size` exists because `length` cannot: a scale-ts codec is an `[enc, dec]` tuple, so its `length` is fixed at 2.

The behavioural change comes with it — a fixed-size codec throws on an over-long value and zero-pads a shorter one, where scale-ts silently truncated and under-filled. See [fixed-size codecs](#fixed-size-codecs-no-longer-truncate-silently) for what that means in practice.
