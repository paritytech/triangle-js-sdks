# Migration Guide: v0.12 → v0.13

This guide covers the breaking changes in v0.13, which aligns the SDK with the codec-3 wire of the
[truapi specification](https://github.com/paritytech/host-rust-core/tree/main/rust/crates/truapi).

- [**Codec 3 wire format**](#codec-3-wire-format), every frame is addressed by `(trait, method, message_type)`
- [**Nested API**](#nested-api), `hostApi`, the transport and the container are grouped by trait and use the spec's
  method names
- [**Typed interrupts**](#typed-interrupts), every subscription ends with a clean completion or an error
- [**Renderer replaces the chat custom renderer**](#renderer-replaces-the-chat-custom-renderer)
- [**Payload changes**](#payload-changes), `createTransaction` contacts, `OptionBool`, `localStorage.read` v2
- [**New methods**](#new-methods), pocket, contacts, unwatermarked signing, permission authorization

> **v0.13 is wire-incompatible with every earlier release.** Hosts and products must be upgraded together; a v0.12
> peer never completes the handshake (a v0.13 product sends codec version 3). The payment and coin payment payloads of
> v0.11/v0.12 are unchanged. There is no session or key impact.

---

## Codec 3 wire format

A frame used to be `[requestId][flat index][payload]`, the index spending two slots per request method and four per
subscription. It is now

```text
[requestId: SCALE str][trait: u8][method: u8][message_type: u8][payload bytes...]
```

- `(trait, method)` is truapi's wire table: one id per method, grouped by trait (`account` is trait 2,
  `account.getAccount` is `(2, 1)`). The ids are in `hostApiProtocol.<trait>.id` / `.methods.<method>.id`.
- `message_type` names the leg: `request` 0 / `response` 1 / `cancel` 4 for a request; `start` 0 / `receive` 1 /
  `interrupt` 2 / `stop` 3 for a subscription (`MessageType` in `@novasamatech/host-api`).
- The version tag moved **inside** the result. A response is `Result<Versioned<Ok>, CallError<Versioned<Err>>>`, an
  interrupt `Result<(), CallError<Versioned<Err>>>`; a stop or cancel carries no payload.
- `CallError` gained `Cancelled` (index 5).
- An inbound request for an address the receiver does not know is answered with a protocol error on the reserved
  `(255, 255)` address, and the caller's request settles as `Unsupported`.
- The handshake negotiates codec version **3** (`SCALE_CODEC_PROTOCOL_ID`), and only an `Ok` answer connects.

Value shapes seen by handlers and callers did not change: requests and items are `{ tag: 'v1', value }`, responses
`{ tag, value: Result | CallErrorMarker }`.

### Cancellation

Aborting the signal of a request now withdraws it on the wire:

```ts
const controller = new AbortController();
hostApi.contacts.pick(enumValue('v1', {}), { signal: controller.signal });
controller.abort(); // sends `cancel`; the call rejects at once
```

The host's handler receives `{ signal }` and sees it abort; the transport answers `CallError::Cancelled` and drops
whatever the handler resolves with afterwards.

### Low-level transport and debug events

`transport.postMessage(frame)` and `transport.listenMessages(cb)` deal in raw `Frame`s
(`{ requestId, traitId, methodId, messageType, payload }`). `DebugMessageEvent.payload` and
`HostApiDebugMessageEvent.payload` are a `DecodedMessage` (`{ trait, method, traitId, methodId, leg, value }`) instead
of the old flat enum. `HostApiMethod` and `MessagePayloadSchema` are removed.

## Nested API

Every surface is grouped by trait and uses the spec's method names.

```ts
// v0.12
hostApi.accountGet(enumValue('v1', [dotNs, 0]));
hostApi.chainHeadFollowSubscribe(args, cb);
transport.request('host_local_storage_read', payload);
container.handleAccountGet(handler);
container.handleChatBotRegistration(handler);

// v0.13
hostApi.account.getAccount(enumValue('v1', [dotNs, 0]));
hostApi.chain.followHeadSubscribe(args, cb);
transport.request('localStorage', 'read', payload);
container.account.handleGetAccount(handler);
container.chat.handleRegisterBot(handler);
```

| ------------------------------------------------ | ------------------------------------------------------------- |
| `info` / `handleInfo`                            | `system.info` / `system.handleInfo`                           |
| `featureSupported`, `navigateTo`, `getProductContext` | `system.*`                                                    |
| `devicePermission` / `handleDevicePermission`    | `permissions.requestDevicePermission` / `handleRequestDevicePermission` |
| `permission` / `handlePermission`                | `permissions.requestRemotePermission` / `handleRequestRemotePermission` |
| `pushNotification`, `pushNotificationCancel`     | `notifications.sendPushNotification`, `cancelPushNotification` |
| `deriveEntropy`                                  | `entropy.derive`                                              |
| `localStorageRead` / `Write` / `Clear` / `Subscribe` | `localStorage.read` / `write` / `clear` / `subscribe`         |
| `workerBeginOperation`, `workerEndOperation`     | `worker.beginOperation`, `worker.endOperation`                |
| `accountConnectionStatusSubscribe`               | `account.connectionStatusSubscribe`                           |
| `accountGet`, `accountGetAlias`, `accountCreateProof`, `accountSignVrf` | `account.getAccount`, `getAccountAlias`, `createAccountProof`, `signVrf` |
| `getUserId`, `requestLogin`, `getLegacyAccounts`, ring VRF methods | `account.*` (same names)                                      |
| `createTransaction*`, `signRaw*`, `signPayload*` | `signing.*` (same names)                                      |

The container keeps `handleChainConnection`, `isReady`, `dispose`, `subscribeProductConnectionStatus` and
`onDebugMessage` at the top level. Container request handlers receive `(params, { ok, err, signal })`. Chain requests
answer `Unsupported` until `handleChainConnection` is called instead of hanging, and calling it again replaces the
previous wiring.

The `host-api-wrapper` provider APIs (`createAccountsProvider`, payments, coin payment, chat, …) keep their shapes except
where noted below.

## Typed interrupts

Every subscription now has an interrupt error type. Those that had none (theme, locale, chat list and actions, account
connection status, chain follow, preimage lookup, statement store, local storage, and the new renderer and pocket
subscriptions) carry `GenericError`. On the transport and `hostApi`, an interrupt value of `undefined` is a clean
completion.

```ts
// host
interrupt({ tag: 'v1', value: undefined }); // clean completion
interrupt({ tag: 'v1', value: new GenericError({ reason: 'gone' }) });
```

In `host-api-wrapper`, `onInterrupt` receives the method's own error or `undefined`; transport failures are folded into
that error (`X.Unknown({ reason })`, or `CoinPaymentErr.Internal` for coin payment). Formerly `Subscription<void>`
results are `Subscription<GenericInterrupt | undefined>`.

A container subscription without a registered handler now interrupts with an `Unsupported` failure instead of
completing cleanly; payment and coin payment keep their domain defaults.

## Renderer replaces the chat custom renderer

truapi retired chat method 5 (`custom_message_render`) in favour of a `renderer` trait that draws product bodies in
chat messages, input widgets and Pocket cards.

- `renderer.render` is **host-initiated**: the host starts it with `{ context: RenderContext, payload }`, the product
  streams `RendererNode` trees. Clicks and value changes inside those bodies arrive on `renderer.actionSubscribe` as
  `{ context, actionId, payload: Uint8Array }` — chat `ActionTriggered` now only reports host-drawn `Actions` buttons.
- `CustomRendererNode` → `RendererNode`. `Spacer` is `{ modifiers }`, `TextField` is `{ modifiers, props }` (neither
  has children). New `Image` and `Effect` nodes, `Shape.Square`, and `opacity` / `blendingMode` modifiers.
- A `TextField` value change carries the new value as plain UTF-8 bytes, not a SCALE string.

```ts
// v0.12 — product
chat.onCustomMessageRenderingRequest(matchChatCustomRenderers({ poll: renderPoll }));
// v0.12 — host
container.renderChatCustomMessage({ messageId, messageType, payload }, render);

// v0.13 — product
productRenderer.onRender(matchChatMessageRenderers({ poll: registerChatMessageRenderer(...) }));
// v0.13 — host
container.renderer.render({ context: enumValue('ChatMessage', { roomId, messageId, messageType }), payload }, render);
```

`chat.onCustomMessageRenderingRequest`, `ChatCustomMessageRenderer(Params)` and `matchChatCustomRenderers` are
removed. See the `host-api-wrapper` and `product-react-renderer` READMEs.

## Payload changes

- **`signing.createTransaction`** carries `contacts: ContactHandle[]` last: handles from `contacts.pick` that
  `callData` names. The host substitutes the resolved accounts before signing or showing anything, and refuses with the
  new `CreateTransactionErr.UnknownContact` (appended) when it cannot resolve one. `getProductAccountSigner` takes
  `{ contacts }` and defaults to `[]`. A host relaying to Polkadot Mobile through `host-papp` must substitute the
  handles first: the SSO message keeps the old shape without `contacts`.
- **Signing payloads** encode `withSignedTransaction` as `OptionBool` (`false` is `0x02`), matching truapi. The
  TypeScript type is unchanged.
- **`localStorage.read`** gained `v2` (`{ product, key }`), which reads another product's storage when that product's
  manifest grants the caller the `storage` scope; it fails with `StorageReadV2Err.AccessNotGranted` otherwise.
  `container.localStorage.handleRead` receives the v2 shape and upgrades v1 requests; a v1 caller gets
  `AccessNotGranted` as `StorageErr.Unknown`. In the wrapper: `readBytes/readString/readJSON(key, product?)`.
